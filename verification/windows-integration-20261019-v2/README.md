# Native Windows communication acceptance

2026-10-19: 21/21 assertions passed for a native Windows 11 x64 OpenCode **1.19.0** chat and a macOS arm64 OpenCode **2.0.20** chat. Both were ordinary, explicitly owned test chats seeded before attachment. Transport used the existing FRP network and real SSH in both directions. Windows used a private Node **24.22.0** runtime and an independent embedded ledger; no WSL or hcom Windows binary was used.

The exact communication runtime is commit **f1feccb**, with per-file SHA-256 values in [metrics.json](metrics.json). [assertions.json](assertions.json) contains the individual checks. Four actual model shell-tool executions produced four signed global messages: one request and one correlated reply in each direction. All four sends reached `remote-stored`; exact native input, model tool completion, native final answers, duplicate delivery and rejection evidence were inspected separately. Both native models remained `opencode/deepseek-v4.1-flash-free`; selected catalogs advertised zero prices and all observed assistant costs were zero. Four exact command approvals were granted once, without saved permission changes.

The owner fixture supplied bounded project questions, exact communication commands and reply text. This verifies the native tool path, directed cross-machine delivery, receipt mapping and correlated replies. It is not an evaluation of open-ended autonomous collaboration or a causal test that the model obtained every fact exclusively from its original context.

The same signed message was replayed through SSH and retained its original remote event. Changed content under the same ID, an invalid signature, an unaccepted room, and an incorrect expected session were rejected. Windows native user-input IDs and ledger counts did not increase. The runtime files on both hosts matched before cleanup; full configuration, identities, paths, model transcripts and permission requests remain in private diagnostics rather than this public repository.

Both test bindings were detached and the original chats were preserved. The real cleanup stage exposed a separate Task Scheduler DACL issue: an elevated SSH registration gave the Limited task principal only read access. The two stopped owned tasks were then removed by the original exact ownership-checking cleanup function from the operator process. The corrected registration DACL and a fresh Limited-token self-cleanup are verified separately; this acceptance does not retroactively claim that the initial tasks cleaned themselves.

The [read-only observer result](../windows-observer-20261019-v1/metrics.json) checks the same conversation after workers stopped: six logical messages including two operator requests, four merged cross-machine messages and two reply links, with both source states unchanged by observation.
