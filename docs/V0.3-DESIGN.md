# v0.3 多节点与多harness实施合同

状态：IMPLEMENTING。用户2026-10-17明确要求继续开发多机、多harness；本文新增该范围的合同，不改写此前计划。

每个节点运行本地hcom账本与原生adapter。首轮使用SSH stdio交换签名消息，复用SSH主机校验与已有网络，不开放模型服务端口或远程launch/kill/config。hcom现成relay会同步整个state域的事件/元数据，因此本轮不启用公共MQTT。PC只读SSH预检当前不可达，真实跨主机结果与同机双节点结果分开记录。

## 会话与adapter

adapter统一discover/list/session/prompt/inbox/messages/close/capabilities；OpenCode保留现有精确API。Codex连接实际共享daemon的原生协议，不新开服务冒充已有实例。默认attach只接现有loaded thread；用户显式--resume时允许在原daemon恢复该原thread，不创建新thread或宣称接入当前桌面聊天。原生queue的受理与实际启动分别记录，未知提交按稳定client输入ID对账。

## 节点与配对

每空间生成Ed25519密钥，完整公钥hash为nodeId，私钥只保存在0600本地state。node export输出签名卡片与本节点活动binding；peer add显式固定公钥和SSH/本地测试进程地址。alias首版要求参与节点间不重名，真实身份仍由node/binding/revision组成。同一state不得克隆成两个活动节点。

room在一端创建，export后在另一端显式import。双方接受同一room ID/revision、成员node/binding/revision与manifest hash。配对不自动授权加入本机任何room。

## 消息与账本

wire message包含全局m_UUID、room/revision/hash、双方node/binding/revision/alias、replyToMessageId和正文，签名覆盖全部内容。接收验证固定peerkey、来源归属、已接受room、双方pins及reply关系。相同ID同hash返回原回执，异hash拒绝。

正文仍在各节点hcom账本；outbox/inbox只保存global ID→localeventId、hash、状态与绑定引用。接收写入hcom前保存pending意图；重试从账本按global ID补全映射，不能盲目重写。控制锁覆盖写账与映射提交。worker交入原生上下文前再次检查签名与映射、room、原生session。

```text
send: validate local owner + room; sign wire; persist outbox intent
      append to local hcom transport endpoint; save local event ID
      SSH peer's fixed node receive, input only via stdin
receive: verify signature + room + pins + reply; save pending intent
         reconcile ledger by global ID; append only if demonstrably absent
         save inbox mapping; return signed stored receipt
worker: verify ingress mapping/signature; validate exact native session
        persist pending native input; submit/reconcile; record native-admitted
```

stored、native-admitted、模型reply三种证据分开；无法确认的状态暂停/保留，不宣称exactly-once。别名/--from仍是同一可信用户下的模型寻址，节点签名不等于模型不可伪造身份。
